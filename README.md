# Yoyaku

Yoyaku는 Mac에서 한국어와 일본어 예약 대화를 통역하는 앱입니다. 점원이 일본어로 말하면 한국어 자막을 읽고, 내가 한국어로 답하면 그 말을 일본어 음성으로 들려줍니다. 예약 상황을 골라 혼자 연습하거나 브라우저에 두 사람의 음성을 연결해 통역할 수 있습니다. 전화 연결과 끊김은 모의 환경에서 시험할 수 있고, 실제 가게 번호로 발신하는 기능은 아직 지원하지 않습니다.

## 제품 요구사항

| 사용자가 하려는 일 | 앱의 동작 |
| --- | --- |
| 점원(A)의 말을 듣는 동안 뜻을 읽기 | 질문뿐 아니라 “잠시 기다려 주세요” 같은 안내와 짧은 맞장구도 한국어로 보여 줍니다. 말이 이어지면서 인식 결과가 달라지면 자막도 고칩니다. |
| 사용자(B)가 원하는 때 한국어로 답하기 | 무엇을 말하고 언제 끼어들지는 내가 정합니다. 앱은 뜻이 분명해진 구간부터 일본어로 읽어 주며, 재생 중인 음성은 직접 멈출 수 있습니다. |
| 예약 내용 확인하기 | 원문과 번역을 나란히 보고 날짜·인원·이름이 맞는지, 거절이나 정정이 빠지지 않았는지, 예약을 요청한 것인지 이미 확정한 것인지 확인합니다. |
| 실제 통화 전에 연습하기 | 대본 15개로 점원의 말을 듣고 답하는 연습을 할 수 있습니다. 통화 중이나 무응답 같은 전화 상황은 별도의 Twilio 모의 환경에서 시험합니다. |

## 실행 환경과 시작 방법

| 준비 항목 | 필요한 이유 |
| --- | --- |
| macOS, Go 1.25 이상, Cgo, Xcode Command Line Tools | Go가 앱과 CLI를 빌드하고 Cgo가 whisper.cpp를 연결합니다. 실행 스크립트는 프로젝트의 `.local-go/go/bin/go`를 먼저 찾고, 없으면 시스템의 `go`를 사용합니다. [Go 모듈](go.mod) · [고정 도구 체인](go-toolchain.json) |
| 최초 다운로드용 인터넷과 디스크 공간 | 기본 가중치는 Gemma 약 14.62 GB와 Whisper 약 0.49 GB입니다. 엔진·다운로드 임시 파일·빌드 캐시 공간도 필요합니다. 설치 후 음성 인식과 번역은 로컬에서 실행합니다. [모델 파일과 크기](models.json) · [엔진 버전](native-runtimes.json) |
| 메모리 | 실험에는 통합 메모리 48 GiB인 M4 Pro를 사용했습니다. 다른 앱을 함께 쓸 때 모델에 24~36 GB를 배정하는 방안을 검토했습니다. 앱 전체에 필요한 최소 메모리는 아직 측정하지 않았습니다. [모델별 측정 조건](benchmark/README.md) |
| 브라우저와 오디오 장치 | 마이크 연습에는 브라우저 마이크 권한, 일본어 음성 재생에는 macOS Kyoko 음성이 필요합니다. 양방향 통역에는 한국어 마이크와 일본어 오디오를 공유하는 탭 또는 서로 다른 두 입력 장치를 사용합니다. 한쪽 언어만 시험할 때는 마이크 하나로 충분합니다. |

```sh
./yoyaku setup          # 처음 한 번 실행해 엔진과 기본 모델을 내려받고 파일을 검증합니다.
./yoyaku serve          # 앱을 실행합니다. 종료하려면 Ctrl-C를 누르세요.
```

- **문장별 연습**에서는 점원 문구를 듣고 마이크 또는 직접 입력으로 답합니다. [예약 연습 열기](http://127.0.0.1:3002/)
- **연속 통역**에서는 입력 장치와 언어 방향을 고르고 통역을 시작합니다. 일본어 탭을 입력으로 쓸 때는 탭 선택 창에서 오디오 공유도 켜세요. [연속 통역 열기](http://127.0.0.1:3002/live)

## 전체 시스템 구조

`./yoyaku serve`는 웹 앱·음성 인식 서버·모델 관리자를 한 Go 프로세스에서 실행합니다. 모델 관리자는 별도 자식 프로세스로 LLM 하나를 띄웁니다. 서비스 간 연결은 이 Mac의 루프백 주소를 사용합니다.

```text
브라우저 (JavaScript)                         Mac에서 실행되는 서비스
  |
  +-- /      예약 대본, 마이크, 직접 입력 --HTTP--+
  +-- /live  점원/사용자 오디오 ------------WS---+--> 웹 앱 :3002 (Go)
                                                      |
                                                      +-- 문장 연습 / 연속 통역 제어
                                                      |     |
                                                      |     +-- 작업 큐 --HTTP--> 음성 인식 :8092
                                                      |     |                       +-- Cgo -> whisper.cpp
                                                      |     +-- 작업 큐 --HTTP--> llama-server :8091
                                                      |                            (GGUF, 모델 추론)
                                                      +-- 모델 관리자 :8093
                                                      |     +-- :8091 자식 프로세스 시작 / 종료 / 전환
                                                      +-- /api/speak -> macOS say (Kyoko)
                                                                          |
브라우저 스피커 <---------------------------- 일본어 WAV -------------------+

독립 실행   ./yoyaku phone-demo
  브라우저 :3000 <--> Go 모의 전화 앱 <--> Twilio 모의 제공자 :3001
```

브라우저는 각 언어의 녹음을 16 kHz 모노 PCM16 WAV로 보냅니다. **Whisper**는 무엇이라고 말했는지 받아쓰고 각 부분이 녹음의 어디쯤인지 표시합니다. **Go 제어기**는 인식 결과가 안정됐는지 확인합니다. **언어 모델(LLM)**은 지금까지 들은 말만으로 뜻이 통하는지 판단하고 한국어와 일본어 사이의 번역을 맡습니다. 모델 계산은 C++/Metal 엔진에서 실행하므로 앱을 쓰기 위해 Node.js나 Python을 설치할 필요는 없습니다.

```text
점원(A)의 일본어 -> 인식 원문 -> 잠정 한국어 자막 -> 원문 수정 시 자막 갱신
                            +-> 안정된 구간 + R -> 확정 한국어 자막

사용자(B)의 한국어 -> 인식 원문 -> 안정된 구간 + R -> 일본어 번역
                                                   +-> FIFO -> 일본어 음성 재생
사용자가 재생 중단 -> 이전 출력 무효화 -> 브라우저 재생 취소 -> 중단 확인
```

가령 “취소하려고요”만 들었다면 번역할 수 있지만, “취소하려고요, 아, 그게 아니라…”까지 들었다면 정정 내용을 기다려야 합니다. 모델은 그 시점까지 들은 말로 뜻이 통하면 `R`, 더 들어야 하면 `W`를 돌려줍니다.

Go는 두 번 연속 같은 구간이 인식되고 그 원문이 600 ms 동안 유지되는지 확인합니다. 구간 뒤로 400 ms 이상의 오디오가 더 들어왔거나 700 ms 이상의 무음이 있으면 모델에 판단을 요청합니다. `R`을 받더라도 원문이나 세션이 바뀌었는지, 기한 안에 응답이 왔는지, 오디오에서 해당 구간의 끝을 찾을 수 있는지 다시 확인한 뒤 확정합니다.

## 예약 상황을 직접 테스트하기

브라우저, CLI, 오프라인 테스트는 아래 15개 대화를 같은 파일에서 읽습니다. [예약 대화 원본](testdata/reservations/scenarios.json)

| 분류 | 케이스 ID | 직접 확인할 부분 |
| --- | --- | --- |
| 기본 예약 | `normal-booking` | 날짜·인원·시간·이름·최종 접수 |
| 대체 시간 | `alternative-accepted`, `alternative-declined` | 제안·수락·거절과 실제 시간 |
| 만석·연락 | `fully-booked-callback` | 답변이 필요 없는 안내, 연락 동의, 번호 |
| 이름 | `name-repetition` | 이름 음차와 반복 요청 |
| 잘못된 날짜 | `wrong-date-readback` | 잘못 복창한 원문과 사용자의 정정 |
| 인원 | `party-match`, `party-mismatch` | 확인 질문, 두 명/네 명과 정정 |
| 발화 흐름 | `stt-revision-pause`, `interrupt-and-ack` | 멈춤·짧은 맞장구·정정의 의미 보존 |
| 조건 | `fee-and-cancellation-terms`, `seat-and-allergy` | 가격·수수료·좌석·알레르기·부정 |
| 변경·취소 | `change-existing-booking`, `cancel-existing-booking` | 날짜 변경과 취소, 요청과 완료 상태 |
| 대기·전환 | `hold-and-transfer` | 대기 안내와 담당자의 반복 질문 |

1. 화면에서 케이스를 고르고 **연습 시작**을 누릅니다.
2. A의 일본어 음성을 듣고 한국어 자막을 확인합니다.
3. B 차례에 **마이크로 답하기**를 누르고 자유롭게 한국어로 답합니다. 직접 입력도 가능합니다.
4. 화면에 받아쓴 원문부터 확인합니다. “두 명”을 다르게 알아들었다면 같은 말을 직접 입력해 번역해 보세요. 음성 인식에서 생긴 오류인지 번역에서 생긴 오류인지 구분할 수 있습니다.
5. 번역 아래의 **기대 의미/참고 번역**을 펼쳐 비교하고, 케이스별 확인 항목을 직접 체크합니다.
6. **다음 점원 문구**로 진행하고 **테스트 기록 저장**으로 JSON을 내려받습니다.

두 명을 네 명으로 고치는 연습부터 시작할 수 있습니다. [인원 정정 케이스 열기](http://127.0.0.1:3002/?scenario=party-mismatch)

저장한 JSON에는 연습한 상황과 차례, 실제 원문과 번역, 사용한 모델과 프롬프트 버전, 처리 시간, 음성 인식 정보, 직접 체크한 항목이 들어갑니다. 원본 녹음은 포함하지 않습니다. 기록을 보관하려면 다른 상황으로 바꾸거나 연습을 다시 시작하기 전에 내려받으세요.

점원은 내가 어떤 답을 해도 대본의 다음 문구를 말합니다. 한국어 답변은 자유롭게 바꿔도 됩니다. 화면의 참고 일본어는 예시 답변을 옮긴 것이므로, 다른 말을 했다면 내가 실제로 말한 뜻이 전해졌는지 확인하세요. 이 화면에서는 녹음을 마치면 번역이 나옵니다. 말하는 도중 자막이 바뀌는 모습은 `/live`에서 볼 수 있습니다.

```sh
./yoyaku scenarios list
./yoyaku scenarios show party-mismatch  # 대화 원문·참고 번역·확인 항목
./yoyaku scenarios json                # 전체 공통 케이스 JSON
```

## 번역 시점 판단 테스트

예를 들어 점원이 가게 이름을 한 음절씩 말하면 첫 음절부터 번역하기는 어렵습니다. 테스트에서는 원문이 조금씩 늘어날 때 **언제 제어기가 모델에 물어보는지**, **모델이 어떤 답을 주면 어디까지 확정하는지**를 따로 확인합니다. 구간을 고르는 코드는 `internal/interpreter/segment.go`, 결과를 확인하고 확정하는 코드는 `internal/interpreter/session.go`, 판단에 쓰는 프롬프트는 `internal/worker/prompts.json`에 있습니다.

```text
  지금까지 인식한 원문과 오디오
       |
       v
  Go가 안정성과 오디오 근거 확인 -- 근거 부족 --> 다음 관측까지 대기
       |
       v
  LLM이 후보 원문의 의미 판단 ---- W --------> 이어지는 말 대기
       |
       R
       v
  Go가 현재 원문 재검사 -> 구간 확정 -> 대응하는 오디오만 소비
```

- 시간 순서대로 재생하는 사례 12개에는 한 음절씩 들어오는 인사, 짧은 맞장구, 만석 안내, 말을 멈춘 조건절, 인원 정정과 부정, 긴 무음, 뒤가 덜 들어온 문장이 있습니다. 같은 녹음을 다시 인식해 원문이 바뀌거나 구간 끝을 판단할 근거가 부족한 경우도 다룹니다. [시간 순서별 사례](testdata/decision/streams.json)
- 기본 평가 문구 48개로는 언어 모델이 그 문구만 보고 뜻이 완결됐는지 판단하는 능력을 확인합니다. 실험 간 비교를 위해 해석이 애매한 문구도 처음 붙인 라벨을 유지합니다. [기본 판단 문구](testdata/decision/readiness.json)

```sh
make test-decision                    # 모델 없이 타이밍·상태 전이 회귀 테스트
./yoyaku decision list
./yoyaku decision run ja-greeting      # 실제 활성 LLM, 선택한 스트림 하나만 재생
./yoyaku decision run ko-condition-pause
```

모델 없이 동작을 점검하려면 `make test-decision`을 실행하세요. 모의 모델이 정해진 R/W를 돌려주므로, 실패한 사례에서 판단을 잘못 요청했는지, 응답을 받은 뒤 잘못된 구간을 확정했는지 찾을 수 있습니다.

실제 모델의 답이 궁금하다면 `./yoyaku serve`를 실행해 둔 뒤 다른 터미널에서 `decision run`을 사용하세요. 이 명령은 준비해 둔 인식 원문을 실제 Go 제어기와 LLM에 차례로 보냅니다. 시계는 가상이므로 5초짜리 무음도 즉시 재생합니다. 마이크·음성 인식·번역·음성 합성은 이 검사에서 실행하지 않습니다. 화면과 `.artifacts/decision/`의 JSON에서 요청 당시 원문, R/W 응답, 소요 시간, 최종 확정 구간을 확인할 수 있습니다.

모델에 판단을 요청할 때는 그때까지 들은 말만 사용합니다. 기대 답, 이후 발화, 참고 번역, 수동 확인 항목은 모델에 보내지 않습니다. 원문의 앞부분만 확정하면 뒤에 남은 오디오는 다음 판단에 사용합니다.

## 프로젝트 구조

```text
  cmd/yoyaku/             Go 실행 진입점
  internal/
    app/                  HTTP·WebSocket·마이크 연습 API·macOS TTS
    decision/             R/W 입력 계약·라벨 검증·스트림 케이스 로더
    interpreter/
      decision_test.go        안정화·조건절·정정·타임스탬프 회귀
      decision_stream_test.go 공통 12개 스트림의 타이밍 재생
      captions_test.go        잠정 자막·원문 수정·늦은 결과 폐기
      playback_test.go        재생 순서, 중단한 음성의 폐기, 브라우저의 중단 확인
      scenarios_test.go       15개 A/B 대화의 원문 전달
      session_test.go         입력 제한, 세션 종료, 응답 시간 초과, 요청이 밀릴 때의 처리
    scenario/             예약 케이스 공통 로더·검증
    worker/               실제 모델 HTTP·관측 원문만 담은 요청·큐
    model/                설치·SHA 검증·모델 프로세스 소유권
    speech/               WAV·언어·무음·동시 요청 검증
    nativewhisper/        Cgo ABI와 whisper.cpp 연결
    phone/                독립 Twilio 모의 제공자·입력형 예약 앱
    cli/                  scenarios / decision / benchmark 등
    research/             벤치마크 문서 링크와 로컬 실험 원본 점검
  testdata/
    reservations/         수동 연습·대화 테스트 공통 케이스
```

## 검증과 로컬 LLM 벤치마크

```sh
make test                # 전체 Go 테스트, race detector, 모델 설치 불필요
make test-decision       # 번역 시점 판단에 집중
make test-scenarios      # 예약 케이스 스키마와 A/B 대화 전달
make vet
./yoyaku verify          # 벤치마크 문서 링크 점검. 로컬 원본이 있으면 해시와 평가 기록도 검증
./yoyaku check           # 실제 활성 LLM의 작은 R/W·번역 점검
./yoyaku check-audio path.wav ko
./yoyaku check-live      # 합성 음성으로 실제 ASR·LLM·WS·TTS 연결 확인
```

`check-live`를 실행하려면 앱을 켜 두고 사용 중인 연속 통역 세션을 종료하세요.
합성 음성 두 개로 일본어 입력이 한국어 자막으로 나오고, 한국어 입력에서 일본어 음성이 생성되는지 점검합니다. [점검용 음성 안내](testdata/audio/README.md)

모델을 고를 때는 같은 예약 문구에서 어느 모델이 뒷말을 기다렸고 어떤 모델이 날짜나 인원을 잘못 옮겼는지 비교해 보세요.
모델별 메모리 사용량과 자막·음성 재생까지 걸린 시간도 기록했습니다. [로컬 LLM 실험 기록](benchmark/README.md)

```sh
./yoyaku benchmark             # 기본 문구 48개의 번역 시점 판단, 24문장 번역
./yoyaku benchmark disfluency  # 머뭇거림·정정이 있는 34개 시점 판단, 예약 문장 20개 번역
```

앱을 실행하고 모델을 선택한 뒤 위 명령을 직접 실행하면 결과가 `.artifacts/native-benchmark/`에 저장됩니다.
두 명령 모두 번역 전용 모델에서는 번역만 실행합니다.
머뭇거림 실험에서는 같은 사람의 말을 여러 시점에서 끊고, 각 시점까지 들린 원문을 모델에 보냅니다.
억양에 따라 판단이 달라지는 네 문구는 실험 전에 `?`로 표시하고 점수에서 뺍니다.
명령은 모델의 응답과 소요 시간을 기록합니다.
새 번역의 뜻을 평가할 때는 원문과 번역문을 읽고 어떤 사실이나 조건이 달라졌는지 적습니다. [번역 시점 판단 문구](testdata/decision/disfluency.json) · [예약 문장별 확인 항목](testdata/translation/reservation-intent.json)

## 모델·포트·전화 모의 환경

기본 번역 모델은 Gemma 4 26B-A4B Q4_0 GGUF이고, Whisper small이 음성을 받아씁니다.
한 번에 LLM 하나를 불러오며 기본 문맥 길이는 8,192토큰, 호스트 캐시는 128 MiB입니다.
가중치 외에도 GPU 연산, 모델의 문맥 캐시(KV), 브라우저가 쓸 메모리가 필요합니다.
`--fit-target 8192`는 모델을 불러올 때 남겨 두려는 여유 메모리의 목표값입니다.
앱이 실제로 사용한 메모리는 모델별 측정표에서 확인할 수 있습니다. [모델별 메모리](benchmark/resources.md) · [모델 버전·크기·해시](models.json) · [엔진 버전](native-runtimes.json)

```sh
./yoyaku models list
./yoyaku models setup 4b
./yoyaku models switch 4b        # 연속 통역을 종료한 뒤
./yoyaku models switch gemma26b
./yoyaku phone-demo             # 독립 모의 제공자 + 입력형 예약 UI
```

`./yoyaku models list`에서 원하는 모델의 ID를 찾고, 처음 쓰는 모델은 `./yoyaku models setup 프로필ID`로 먼저 설치하세요.
연속 통역에는 번역 시점 판단과 번역을 모두 할 수 있는 범용 모델을 사용합니다.
예를 들어 Gemma E4B는 `gemmae4b`, Qwen3.5 9B는 `qwen9b`, Cohere Tiny Aya Water는 `tinyayawater`로 선택합니다.
Tencent HY-MT1.5의 `hymt18b`와 `hymt7b`, TranslateGemma의 `translate12b`는 문장 연습에서 쓸 수 있는 번역 전용 모델입니다. [모델별 비교 결과](benchmark/models.md)

| 포트 | 역할 |
| --- | --- |
| 3002 | 예약 연습·연속 통역 HTTP/WS |
| 8091 | 네이티브 llama-server |
| 8092 | Go 음성 서버 + whisper.cpp |
| 8093 | Go 모델 관리자 |
| 3000 | 독립 입력형 전화 모의 UI |
| 3001 | Twilio 형태의 모의 REST·웹훅·Media Streams |

```text
  브라우저 <--> 모의 전화 앱 :3000 (Go)
                    |
                    | REST / 서명 웹훅 / TwiML / WebSocket
                    v
                모의 제공자 :3001 (Go)
                    +-- 정상 예약, 통화 중, 무응답 등 통화 시나리오 8개
                    +-- 8 kHz PCMU 음성 프레임 / mark / clear / stop
                    +-- 점원 대본을 전달하는 별도 제어 경로
```

전화 연습 화면은 준비된 문구와 모의 음성으로 동작합니다. 이 모드에서 Whisper나 Gemma를 호출하지는 않습니다. 실제 가게와 통화하려면 전화망이나 SIP/PBX로 통화를 연결하고 양쪽 음성을 통역기로 전달하는 작업이 더 필요합니다. 제공자만 실행하려면 `./yoyaku mock`을 사용하세요. 모의 계정 ID는 `AC00000000000000000000000000000000`, 토큰은 `local-mock-token`입니다.

연속 통역을 시험할 때는 언어별 입력을 따로 연결하고 헤드폰을 사용하세요. 짧은 말은 처음에 잘못 받아썼다가 더 듣고 고칠 수 있습니다. 실제 마이크와 소음, 8 kHz 전화 음질에서의 인식 정확도는 따로 확인해야 합니다.
Whisper가 같은 오디오 창을 반복 인식하면서 제공하는 타임스탬프로 원문과 오디오의 경계를 맞춥니다. 별도 강제 정렬 모델을 도입하는 방안과 Qwen3-ASR 후보 조사 내용도 기록했습니다. [음성 인식 모델과 정렬 방식 비교](docs/speech-model-comparison.md)
